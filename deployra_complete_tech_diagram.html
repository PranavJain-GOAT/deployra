🍪 HttpOnly Cookie: accessToken
Set by backend via Set-Cookie header.
HttpOnly = JS cannot read it (XSS-proof).
Secure = only sent over HTTPS.
SameSite=Strict = CSRF-proof.

🍪 HttpOnly Cookie: refreshToken
Long-lived (7 days). Only used on POST /api/v1/auth/refresh.
Stored in DB as SHA-256 hash (RefreshToken table).
Allows silent re-authentication without re-login when access token expires.

trust proxy: 1
app.set('trust proxy', 1). Makes Express trust X-Forwarded-For from Render's load balancer. Without this rate-limiter sees Render's internal IP, not user's real IP — breaking all IP-based limits.

Sets 15 security HTTP headers automatically: X-Content-Type-Options:nosniff, X-Frame-Options:DENY (anti-clickjack), Strict-Transport-Security (force HTTPS), Content-Security-Policy, X-XSS-Protection. crossOriginResourcePolicy:cross-origin so Cloudinary images load.

⏱️ Layer 4 — Rate Limiting (express-rate-limit) — OWASP Anti-Brute-Force
authLimiter
Applied to ALL /auth/* routes. 30 req / 15 min / IP. standardHeaders:true adds RateLimit-* response headers per RFC 6585. On breach: Winston logs IP + path, returns HTTP 429 JSON response.
OWASP
loginLimiter
POST /login and POST /register only. 8 attempts / 15 min / IP. skipSuccessfulRequests:true so successful logins don't count against the limit. Logs email on breach. Prevents credential stuffing attacks.
Brute-Force
passwordResetLimiter
POST /forgot-password only. 5 req / 1 hour / IP. Logs email on breach. Prevents account enumeration via password reset endpoint timing side-channel attacks.
Anti-Enum
emailResendLimiter
POST /resend-verification only. 3 req / 1 hour / IP. Prevents email bombing of SMTP provider and exhaustion of email quota from malicious resend spam.
Anti-Spam
Joi validates request body → authenticate verifies JWT → authorize checks role → controller runs
✅ Layer 5 — Validation + Authentication + RBAC Middleware

INPUT VALIDATION (Joi)

validate(schema) middleware
Joi schema validation runs BEFORE the controller. The controller never executes if validation fails.

registerSchema: name (required), email (valid format), password (min 8 chars + complexity), role (CLIENT or DEVELOPER enum).
loginSchema: email + password both required.

Returns HTTP 400 with field-level error messages on failure. Consistent error format prevents information leakage.
Input Validation

JWT AUTH + RBAC

authenticate middleware
Guards all protected routes:
1. Read req.cookies.accessToken
2. Fallback: Authorization: Bearer header
3. jwt.verify(token, JWT_SECRET) → decoded payload
4. prisma.user.findUnique({where:{id: decoded.userId}})
5. req.user = user → next()

Returns 401 if token is missing, expired, or invalid.
Auth Guard
authorize / adminOnly (RBAC)
Role-based access control via req.user.role.
Enum roles: CLIENT | DEVELOPER | ADMIN.
authorize('ADMIN','DEVELOPER') checks role inclusion.
adminOnly = authorize('ADMIN') shorthand.
Returns 403 Forbidden if role does not match.
RBAC
Express Router matches HTTP method + path → controller function invoked

🔑 JWT Access Token (jsonwebtoken)
jwt.sign({userId, role}, JWT_SECRET, {expiresIn:'15m'})
Set-Cookie: accessToken=<token>; HttpOnly; Secure; SameSite=Strict; Path=/
Verified on every protected request. Expires in 15 minutes.
🔄 JWT Refresh Token (jsonwebtoken)
jwt.sign({userId}, JWT_REFRESH_SECRET, {expiresIn:'7d'})
SHA-256 hashed via crypto.createHash before DB storage
Set-Cookie: refreshToken=<token>; HttpOnly; Secure; SameSite=Strict; Path=/api/v1/auth/refresh
Stored in RefreshToken table. Revoked on logout. Rotated on refresh.
🔒 bcrypt Password Hashing
bcrypt.hash(password, 12) on register and change-password
bcrypt.compare(plaintext, storedHash) on every login
Salt rounds: 12 = ~250ms per hash on modern hardware.
GPU brute-force is computationally infeasible. Adaptive — cost factor can increase over time.

1

2
⚠️
Server returns 401
authenticate middleware calls jwt.verify() and it throws TokenExpiredError. Middleware returns HTTP 401 Unauthorized immediately. Request is rejected.

// throws: TokenExpiredError

message:'Token expired'
})
Axios interceptor
3
🔄
Axios response interceptor
Axios sees status 401. The interceptor fires automatically. It sends a silent POST to /api/v1/auth/refresh. The browser auto-attaches the refreshToken cookie.
// interceptor catches 401

// browser sends:
// Cookie: refreshToken=eyJ...
validate DB token
4
🔍
Prisma: validate refresh token
Server reads refreshToken cookie. SHA-256 hashes it. Calls Prisma to find the hash in RefreshToken table and check it's not revoked or expired.
const hash = sha256(cookie)
prisma.refreshToken.findFirst({
where:{tokenHash: hash,
revoked: false,
expiresAt:{gt: new Date()}
}
})
new token issued
5
🍪
New accessToken + retry
Valid refresh token found. jwt.sign() creates a new 15-min accessToken. res.cookie() sets a new Set-Cookie header. Axios gets the new cookie, retries the original request. User sees no interruption.
jwt.sign({userId,role},
JWT_SECRET,{expiresIn:'15m'})
res.cookie('accessToken', newJwt,
{httpOnly:true})
// Original request retried ✓
The entire process (401 → refresh → new cookie → retry) happens in ~200ms. The user never sees a login screen. The original request succeeds on the retry. This is why sessions feel seamless even though the access token only lives for 15 minutes.
